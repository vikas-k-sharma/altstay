# AltStay Console

The split-pane demo console: a WhatsApp-style guest chat on the left, a live knowledge-base
editor on the right. Edit a rule and the next reply reflects it — no save button, no restart.

Part of the [AltStay OS monorepo](../README.md). Talks to [the API](../backend/README.md).

## Architecture

The browser never calls the Spring API directly. It posts to a Next Route Handler, which posts to
the backend.

```
Browser  ──▶  /api/chat (Route Handler)  ──▶  http://localhost:8080/api/v1/chat
              ├─ zod-validates the request
              ├─ forwards upstream problem+json unchanged
              └─ zod-validates the response before returning it
```

Three reasons this is worth an extra hop in dev: `BACKEND_URL` stays server-side and never
reaches the browser (no `NEXT_PUBLIC_` prefix), CORS never applies because the call is
server-to-server, and R1's auth and rate limiting get one obvious home.

Validating the *response* is the step usually skipped. Without it, a backend field rename renders
as `undefined` instead of failing loudly; the handler returns a distinct
`upstream-contract-mismatch` 502 instead.

### Layout

```
src/
├─ app/
│  ├─ page.tsx                 server component — renders ConsoleShell
│  ├─ layout.tsx
│  ├─ globals.css              Tailwind v4 theme tokens
│  └─ api/chat/route.ts        the BFF proxy
├─ components/
│  ├─ console/
│  │  ├─ ConsoleShell.tsx      'use client' boundary — owns both hooks
│  │  └─ SplitPane.tsx         side-by-side at lg+, tabs below
│  ├─ chat/                    ChatPanel · MessageList · MessageBubble · Composer · TypingIndicator
│  └─ admin/                   AdminPanel · RulesEditor · PresetPicker
├─ hooks/
│  ├─ useConversation.ts       messages, send, retry, status
│  └─ useKnowledgeBase.ts      knowledge base + localStorage persistence
└─ lib/
   ├─ contracts.ts             zod schemas — the single source of API truth
   ├─ api.ts                   typed client + ChatApiError
   └─ presets.ts               three seeded Indian hostels
```

`page.tsx` stays a server component so R1 has somewhere to fetch server-side data; `ConsoleShell`
is the client boundary.

### State

Two hooks, `useState`-based. **No state library** — one message list and one in-flight request
doesn't need one, and adding Zustand or Redux here would be ceremony.

`useConversation` appends the user's message optimistically before the request resolves; a chat
that waits 800ms to echo what you typed feels broken. On failure the message is kept and marked
`failed` with a retry affordance, never silently dropped. UI-only fields (`id`, `timestamp`,
`meta`) are stripped before history goes to the API.

`useKnowledgeBase` is a `useSyncExternalStore` store mirrored to `localStorage` (debounced 300ms),
so a stray refresh doesn't wipe rules a beta tester just typed.

> **`getServerSnapshot` must return a stable reference to the pre-`localStorage` defaults.**
> React uses it for the client's *hydration* render as well as the server's, so it is what keeps
> the two trees identical; storage is read only afterwards. Returning a fresh object each call
> causes an infinite-loop warning, and reading storage there reintroduces a hydration mismatch
> that only appears once a user has saved something.

### Environment

`.env.local` (gitignored, already present):

```
BACKEND_URL=http://localhost:8080
```

Server-only by design. Adding a `NEXT_PUBLIC_` prefix here would publish the API endpoint to the
browser and defeat the BFF.

## Tests

10 tests, no backend required — `fetch` is mocked.

- `useConversation.test.ts` — optimistic append, history serialization strips UI-only fields,
  failure preserves the message, retry, clear
- `route.test.ts` — 400 on invalid body without calling upstream, 200 happy path, 502 upstream
  failure, 504 timeout

Component snapshot tests are deliberately absent: they break on every styling tweak and prove
nothing.

## UX behaviours worth preserving

- **Escalation is rendered visibly.** When the AI doesn't know, the UI says so. That's what
  convinces a hostel owner it won't invent a pet policy.
- Per-message `model · tokens · latency`, collapsed by default.
- Autoscroll only when already near the bottom, so scrolling back through history doesn't yank
  you forward.
- Message list is `role="log"` with `aria-live="polite"`; `Enter` sends, `Shift+Enter` newlines.
- Send is blocked with a stated reason when the knowledge base is empty or over 20,000 chars —
  caught here rather than surfacing a backend 400 in the chat transcript.
- Presets exist so a beta tester has something to poke at in three seconds instead of typing a
  knowledge base from scratch. Highest demo value per line of code in the app.

## Limitations

- Single property; knowledge base lives in `localStorage`, not a database.
- No auth — R1.
- No response streaming; replies arrive whole after ~2–3s (Gemini call dominates).
- Conversation resets on refresh. Intended: the knowledge base persists, the chat doesn't.

See [`../.plans/phase-2-review.md`](../.plans/phase-2-review.md).
