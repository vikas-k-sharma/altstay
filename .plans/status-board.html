What's actually built

Everything below runs today, is covered by a passing test, and was watched failing before it was watched passing.

PHASE 1

Stateless concierge API

POST /api/v1/chat — every request carries its own knowledge base and history, no server-side session. Spring AI + Gemini, prompt lives in concierge-system.st, errors normalized to RFC 9457 ProblemDetail.

PHASE 2

Admin panel + guest chat

Split-pane Next.js app: owner-facing knowledge-base editor on one side, WhatsApp-style chat on the other. Knowledge base lives in localStorage; two demo presets ship with it.

Frontend suite green
PHASE 3

Timeout tuning, guardrails, eval harness

Fixed a bug where the Gemini SDK's own retry interceptor silently multiplied the configured timeout by 5–10×. 34-case offline eval corpus, JSONL session capture behind ALTSTAY_CAPTURE_DIR. What's not proven yet: real owners reacting to it.

P4 · TRACK A

Multi-tenant Postgres + RLS

Neon Postgres 18.6, four Flyway migrations. The app connects as altstay_app, not neondb_owner — the default role has BYPASSRLS and would make every policy a no-op. Tenant id is bound per-request by TenantBindingAspect, never client-supplied.

P4 · TRACK B

Auth & roles

Tenant-scoped login (slug + email + password), httpOnly SameSite=Strict session cookie, roles OWNER / MANAGER / FRONT_DESK. CSRF stays off only for /api/v1/**, resting on the invariant that the browser never calls Spring directly.

What's pending

One blocking item, four due before the October sessions, three tracks still to build, three flows deliberately withheld until the gate answers.

P0

The R0 gate has never been asked

The gate is: do the two owners, unprompted, ask when they can have it? No reaction is recorded anywhere — the files under .plans/phase-3-transcripts/ are synthetic fixtures. Sessions are scheduled for October 2026; nothing downstream of R0 should be treated as decided until then.

DUE OCT

Gemini key is on the free tier — 20 requests/day, not per minute

A single beta session asks more than 20 questions. Past that cap every question for the rest of the day renders as "the concierge is offline," and waiting doesn't clear it. This is the most schedule-critical item in the repo.

DUE OCT

Real business names still under backend/src

ChatServiceTest.java, eval/kb/zostel-goa.md, and 16 kbRefs in the eval corpus. Renaming touches the corpus, so it needs a decision, not a quiet edit.

TRACK C

Knowledge base into Postgres

Versioned, dual-path: authenticated tenants read/write Postgres, the anonymous demo keeps localStorage untouched so an auth hiccup never breaks an unrepeatable beta hour.

TRACK D

Rate limiting & token budgets

In-process token bucket first — correct, not just expedient, for one instance. Redis only once there's a second instance or a cross-instance token budget to enforce.

TRACK E

Ops — structured logs, uptime alerting

JSON logs keyed by correlationId, plus a test asserting guest-message text never appears in a log line.

WITHHELD

WhatsApp webhooks, human handoff, guest-thread semantics

Held back deliberately until the R0 gate answers — building them on unverified demand is the risk the gate exists to catch.
