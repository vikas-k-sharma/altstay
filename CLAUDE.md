## Non-obvious constraints

These have each caused a real bug or a failed build. Verify before contradicting them.

- **Spring AI 2.0.1 starter is `spring-ai-starter-model-google-genai`.** The
  `spring-ai-google-genai-spring-boot-starter` name is pre-1.0 and does not resolve.
- **Spring Boot 4 moved autoconfiguration into per-technology packages.** It is
  `org.springframework.boot.jdbc.autoconfigure.DataSourceAutoConfiguration`, *not* the Boot 3
  `org.springframework.boot.autoconfigure.jdbc.…`. Likewise `boot.hibernate.autoconfigure.` and
  `boot.flyway.autoconfigure.`. The old names are what most training data says, and as
  `spring.autoconfigure.exclude` entries **they fail silently** — the first symptom is every
  `@SpringBootTest` dying on *"Failed to determine a suitable driver class."* Read
  `META-INF/spring/org.springframework.boot.autoconfigure.AutoConfiguration.imports` out of the
  resolved jar rather than guessing.
- **`spring-boot-flyway` is a separate artifact and `flyway-core` does not pull it.** Without it
  Flyway sits on the classpath and **never runs** — migrations silently do not apply and the schema
  stays empty while startup looks clean.
- **Next.js 16 diverges from most training data.** Real docs ship at
  `node_modules/next/dist/docs/`. Read them rather than writing Next 14/15 patterns.
  `frontend/AGENTS.md` is generated by `next dev` — never hand-edit.
- **`useKnowledgeBase`'s `getServerSnapshot` must return a stable frozen reference to the
  pre-`localStorage` defaults.** A fresh object per call causes an infinite-loop warning; reading
  storage there causes a hydration mismatch that only appears after a user has saved something.
- **PowerShell:** `curl` aliases to `Invoke-WebRequest` and rejects these flags — use `curl.exe`.
  No `&&`, no ternary (Windows PowerShell 5.1).
- **`ALTSTAY_DB_URL` / `ALTSTAY_DB_USER` / `ALTSTAY_DB_PASSWORD` get no defaults either**, for the
  same fail-fast reason as the API key. The URL carries a password and must use `sslmode=require` —
  the database is reached over the open internet. **This machine is borrowed**, so they live in
  gitignored `backend/.env.properties` (loaded via `spring.config.import: optional:file:...`),
  *not* in persistent user environment variables that would be left behind. Delete it on
  offboarding.
- **Neon's `neondb_owner` has `rolbypassrls = true`.** Verified 2026-08-29 on this project — the
  default role bypasses **every** RLS policy, so an app connecting as it would have a tenancy model
  that enforces nothing while `TenantIsolationIT` still passed. The app connects as **`altstay_app`**
  instead, and that role must be created with **plain SQL**: roles created through the Neon console,
  CLI, or API are granted `neon_superuser`, which carries BYPASSRLS. `neondb_owner` is break-glass
  admin only. Always re-check with
  `select rolsuper, rolbypassrls from pg_roles where rolname = current_user;` — this assumption has
  already been wrong once.
- **Use the database's direct host, never the `-pooler` one.** Tenancy binds the tenant to the
  connection with `SET LOCAL app.tenant_id`; a transaction-mode pooler multiplexes sessions across
  backends, which is a route for one tenant's binding to land in another tenant's query.
- **`channel_binding=require` is libpq-only.** Neon's copy-paste connection string carries it; the
  Postgres JDBC driver does not take it. Keep `sslmode=require`, drop the rest.
- **A slow first query after idle is a cold start, not a timeout.** Free tiers suspend idle
  databases. Don't tune `model-read-timeout` because of it.
- **`GOOGLE_API_KEY` is an env var with no default.** Never write a literal key into a tracked
  file. `mvnw test` (84 unit tests) and `npm run test` (23) both pass without it — verified 2026-08-29.
  Note `ChatClientConfig` carries a `"placeholder-key-for-offline-test"` fallback; fail-fast now
  rests solely on the `${GOOGLE_API_KEY}` placeholder in `application.yaml` having no default.
- **The google-genai SDK always installs its own retry interceptor.** `ApiClient#createHttpClient`
  adds a `RetryInterceptor` unconditionally, defaulting to `attempts=5` with jittered exponential
  backoff — which silently multiplied the read timeout to 13–21s. `ChatClientConfig` pins
  `HttpOptions.retryOptions(attempts(1))` to stop it. **`spring.ai.retry.max-attempts` is a
  different layer and does not reach this interceptor**; don't reach for it when tuning timeouts.
- **When a `customHttpClient` is supplied, `HttpOptions.timeout()` is ignored.** The SDK takes the
  client via `newBuilder()` and never applies it. The OkHttp connect/read/write/call timeouts are
  the ones that take effect. Setting `HttpOptions.timeout()` alongside a custom client is dead
  configuration that reads as working.
- **Log elapsed durations, never configured ones.** `ChatService` logging the configured timeout
  hid a 10× overshoot for a whole phase — the log said `timed out after 2s` while 20s had passed.
- **`src/test/resources/application.yaml` REPLACES `src/main/resources/application.yaml`** on the
  test classpath - it does not merge with it. So any setting that lives only in the main file is
  covered by no test in this repo. This is how Phase 4 §3.3's `SameSite` cookie attribute was
  configured, shipped, and silently absent: the first test to look at the wire saw
  `JSESSIONID=...; Path=/; HttpOnly` and no `SameSite`. Config that must hold in production **and**
  be testable belongs in a bean, not in the main YAML.
  **It has now caught three things**, so assume it will catch a fourth: the `SameSite` attribute
  (fixed with a `CookieSameSiteSupplier` bean), the `altstay.rate-limit` budgets (fixed with
  `RateLimitPropertiesBindingTest`, which loads the main file from the **filesystem** via
  `MainApplicationYamlTestSupport` — `ClassPathResource("application.yaml")` resolves to the *test*
  file, which is the trap one layer down), and `spring.config.import` for `.env.properties`, whose
  absence from the test file meant an `ALTSTAY_MODEL` change never reached `ChatLiveIT`. Both files
  now carry the import.
- **CSRF is disabled on `/api/v1/**` only, and that rests on a load-bearing invariant:** the browser
  never calls Spring directly, only the Next.js BFF does, server-to-server (phase-4 §3.4). **If a
  browser ever gains a direct route to Spring, that decision is void.** Everything outside
  `/api/v1/**` keeps CSRF on.
- **RLS will silently cover for a missing application-level tenant check.** Deleting the tenant
  predicate from `AppUserRepository`'s query left `AuthLoginIT` passing 5/5, because Postgres
  filtered the row the query no longer did. When testing a tenancy guard in the application layer,
  mock the repository - otherwise the test cannot tell the guard from its own absence.
- **The tenant is written into `CurrentTenantHolder` by exactly one thing:** `TenantContextFilter`,
  from an authenticated principal. `set`/`clear` are package-private so nothing else can; tests bind
  through `TenantContextTestSupport` in `src/test`. Keep it that way - it is what makes roadmap
  §4.1's "the tenant id must never be a client-supplied value" a property of the code.
- **A JPA `save()` does not hit the database until flush, so `allocation_no_overlap` fires at
  *commit* — outside the service, after the method returned.** The losing side of a booking race
  then surfaces as an unhandled `DataIntegrityViolationException` and renders as a **500 with a
  Postgres constraint name in it**, which is both the wrong status and a schema leak. Allocations
  are written with `saveAndFlush` so the violation happens where it can be translated into a 409
  a human can act on. Any new write that a database constraint is supposed to guard needs the same
  treatment.
- **The PostgreSQL driver is a `runtime` dependency and is not on the compile classpath.** Writing
  `catch (PSQLException e)` or `instanceof org.postgresql.util.PSQLException` compiles in an IDE and
  fails the Maven build. Pull what you need out of the message or the SQLState instead — and never
  log a `DataIntegrityViolationException`'s message whole: PostgreSQL appends
  `Detail: Failing row contains (…)`, so for `guest` that publishes a real person's name, email and
  phone to the log.
- **`ALTER TABLE … DROP CONSTRAINT` is transactional in PostgreSQL.** To watch a constraint-backed
  test fail, drop the constraint inside a transaction and roll back — the schema is never really
  altered, nothing is left unprotected if the run dies, and the demonstration becomes a test that
  re-runs on every build instead of a manual ritual whose pasted output has to be trusted.
  `AllocationConstraintIT` case 11 is the pattern. This does not work across connections, so a
  multi-threaded race test cannot use it.
- **A randomized test is worth exactly as much as the independence of its oracle.** Phase 5 shipped
  an `AvailabilityCalculatorPropertyTest` whose "brute-force oracle" was the implementation's own
  per-day loop copied into the test: 250 iterations comparing an algorithm to itself, incapable of
  failing. The oracle must reach the answer a structurally different way — the current one
  materializes occupancy night by night where the implementation carries sorted event deltas.
  **Before trusting any test, ask what it would have to see to fail.**
- Build needs `JAVA_HOME` on **JDK 25**; Node lives at `C:\Program Files\nodejs` and is not always
  on PATH.

## Conventions

- **Stateless API.** Every request carries its own knowledge base and history. This is the
  architecture, not a shortcut — it's why a rule edit lands on the next message with no restart.
- Backend: package-by-feature; records for DTOs (Lombok never on a DTO); thin controllers with
  `@RestControllerAdvice` owning errors; RFC 9457 `ProblemDetail`; config via
  `@ConfigurationProperties` records. Synchronous virtual thread execution for model calls.
- Frontend: the browser never calls Spring directly — it goes through the `/api/chat` BFF, which
  zod-validates **both** directions. `BACKEND_URL` stays server-side (no `NEXT_PUBLIC_`). Session capture to JSONL behind `ALTSTAY_CAPTURE_DIR`.
- **Never log guest messages, prompt bodies, or secrets.**
- The prompt lives in `backend/src/main/resources/prompts/concierge-system.st`, not in Java.
